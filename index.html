SecureAI-RAG

68.0% → 1.6% attack success Red-teaming retrieval-augmented generation, and defending it.
  • Built 250 poisoned-document attacks in four families (indirect injection, retrieval manipulation, exfiltration, obfuscation), mapped to the OWASP LLM Top 10 (2025). Target: a clinic Q&A RAG system seeded with 16 canary secrets.
  • A four-stage, independently switchable defense pipeline (ingestion, retrieval, prompt, output) cut attack success from 68.0% to 1.6% across 3 seeds. It keeps 96.5% benign utility at about 0.6 ms added latency for the non-LLM stages, measured with a deterministic simulated LLM reader.
  • Tested an attacker who knows the defenses: 25.7% success (best of 12). Instruction-free retrieval poisoning still succeeds in 83% of adaptive scenarios, a gap that injection-focused defenses miss.
  • Includes a threat model, attack taxonomy, 26 tests and GitHub Actions CI.

Distributed Code Judge

Untrusted code, contained A grading system that runs strangers' code without trusting it.
  • Removed the runner's direct Docker socket access with a policy-enforcing Docker API proxy that validates every container-create request and limits the runner to containers it labelled.
  • Per-test-case sandboxes: all capabilities dropped, no-new-privileges, uid 65534, 64-process and 64 KB output caps, swap disabled, optional gVisor runtime. Code goes in through environment variables, never a shell string.
  • Verified with real-Docker tests for each limit, plus live privilege-escalation, bind-mount and cross-container tampering attempts against the proxy, all run in GitHub Actions CI.
  • At-least-once, idempotent grading: Kafka offsets are committed only after results land in PostgreSQL. Full audited state machine (queued, running, terminal) and per-user rate limiting.
